# 评审问题原型整改说明

日期：2026-09-08。基线：30d9674。范围：自动频率、分环节日志、多类型首页看板、目标端多余数据排查。

## 本轮调整

| 评审问题 | 原型行为 |
| --- | --- |
| 自动频率如何定义 | 同步与一致性核验按根类型分别设置，默认关闭；支持每隔若干小时、每天、每周，时间采用北京时间。显示下次计划时间。自动核验本轮采用抽样，绑定同根类型、允许抽样且范围为全部对象的方案。 |
| 源表到中间表如何监控 | 同步任务详情增加“源表 → 中间表”“中间表 → Manticore”两个环节，按任务编号、根类型、环节精确关联日志，展示读取、写入、异常、跳过及失败明细。 |
| 多类型看板如何组织 | 默认首页采用总览指标、各类型运行表、自动执行计划与重点排查入口。零部件、文档、工艺路线分行展示最近同步和最近核验，支持筛选与下钻。 |
| 目标端多出的记录如何排查 | 从目标对象标识反查源端存在性，区分源端存在、确认多余、待确认及读取异常；显示对象级依据。数量差额只作线索。 |

看板的目标数据量来自当前记录，并显示记录时间；源表和中间表总量没有数据时显示“待获取”。各类型最近一次核验的一致率独立展示，不汇总成全库一致率。进行中任务排除接入重置；跨类型同步任务在总览中按任务去重统计。

## 判断边界

- 本地原型尚未接入自动调度，设置只保留于当前页面会话。刷新后还原；保存配置不代表已经开始自动执行。
- 自动核验暂按抽样设计；同类型任务冲突、错过计划后的补跑规则及其他自动运行方式，仍需在调度接入前确认。
- 分环节日志未上报时显示未知，不从任务整体成功状态推断环节成功。独立示例不属于当前任务、不写入任务集合。
- 多余数据只有在同根类型、同范围、完整且有权限的权威源端查询未找到对象时才确认。查询不完整、权限不足、读取失败都不计入确认多余数。
- 排查示例独立于实际记录，包含完整查询、源端查询不完整、权限不足、读取失败四种场景；不改变看板或核验统计。
- 没有自动删除入口。源端删除、失效同步和目标重复键需要结合实际证据排查。
- 实时服务状态、实际分环节数据上报、源端与目标端存在性查询均尚未接入。本轮是可评审的本地界面与判断逻辑，不是生产验收结论。
